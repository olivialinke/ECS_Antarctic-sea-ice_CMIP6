#### Reproducibility repository

This repository contains the preprocessing and analysis scripts used to produce the results presented in "Uncertainty in climate sensitivity links to Antarctic sea ice".

The workflow includes CMIP6 preprocessing, Antarctic sea-ice diagnostics, radiative-kernel feedback calculations, Gregory-regression ECS estimates, and observational sea-ice analysis.

The repository is designed to document and facilitate reproduction of the analysis. The original CMIP6 model data are not included because of their large volume and should be obtained from ESGF or, where applicable, through ESMValTool. Users without access to DKRZ can download the corresponding datasets from ESGF or ESMValTool and adapt the input paths in the scripts accordingly.

The scripts were developed and executed using Python and CDO. The radiative-kernel calculations use [ClimKern](https://github.com/tyfolino/climkern).

#### Installation

Clone the repository and install the required Python packages:

```bash
git clone https://github.com/olinke95/ECS_Antarctic-sea-ice_CMIP6.git
cd ECS_Antarctic-sea-ice_CMIP6
mamba create -f environment.yml
```

#### Data requirements

The preprocessing scripts operate on the original CMIP6 model output and generate the diagnostics required by the downstream analysis scripts.

The original CMIP6 input data are not included in this repository because of their large volume.

The main required CMIP6 variables are:

- **Antarctic sea ice:** `siconc` and `areacello`.
- **Feedbacks and ECS:** `tas`, `ps`, `ta`, `hus`, `rsus`, `rsds`, `rlut`, `rlutcs`, `rsut`, `rsutcs`, and `rsdt`.
- **Additional diagnostics:** `uas`, `vas`, `tauu`, `tauv`, `huss`, `clt`, `hfls`, and `hfss`.

For the ECS and net feedback calculations, only `tas`, `rlut`, `rsut`, and `rsdt` are required.

## 1. Preprocessing

### `cmip_preprocessing.py`

Preprocesses raw CMIP6 data into a standardized format used throughout the feedback and ECS analysis.

#### Data access

The CMIP model output was accessed from the CMIP data pool at the German Climate Computing Centre (DKRZ). The underlying CMIP datasets remain publicly available through the Earth System Grid Federation (ESGF), including the [ESGF CMIP6 search portal](https://esgf-node.llnl.gov/search/cmip6/).

The preprocessing script is configured to search the DKRZ CMIP data pool and therefore contains DKRZ-specific input directory paths. Users without access to the DKRZ data pool will need to download the corresponding CMIP datasets from ESGF and adapt the input paths in the script accordingly.

#### Purpose

- Searches the DKRZ CMIP data pool for a requested variable and experiment (`piControl` or `abrupt-4xCO2`).
- Identifies all available models.
- Selects the **first ensemble member** (lowest realization number, e.g. `r1i1p1f1`) for each model.
- Merges split NetCDF files into a single continuous time series using CDO.
- Retains only the first **150 years** (1800 monthly time steps).
- Removes models with shorter simulations.
- Replaces the original calendar with a standardized **365-day no-leap calendar** (years 1–150) to ensure consistency across models.
- Converts the `time` coordinate to separate `year` and `month` dimensions.
- Saves one processed NetCDF file per model.

#### Output

One NetCDF file per model:

```text
<variable>_<table>_<model>_<experiment>_<variant>_<grid>.nc
```

The files contain:

- a continuous 150-year monthly time series,
- standardized time coordinates,
- only the first ensemble member.

#### Notes

- Supports both **CMIP5** and **CMIP6**.
- Can be executed independently for each required variable and experiment.
- The processed files are used as input for all subsequent scripts.
- The processed input files can be removed after the downstream analysis has been completed.


## 2. Sea ice

### `SIA-SIE_computation_CMIP.py`

Computes **Sea Ice Extent (SIE)** and **Sea Ice Area (SIA)** for both hemispheres from preprocessed CMIP sea-ice concentration (`siconc`) data.

#### Input data

Requires preprocessed `siconc` data for `piControl` and `abrupt-4xCO2` generated by `cmip_preprocessing.py`, together with the corresponding `areacello` files.

#### Purpose

- Searches the CMIP archive for available `areacello` files and copies a single representative file (first ensemble member) for each model.
- Matches `siconc` and `areacello` files to identify models with complete sea-ice information.
- Computes monthly Northern and Southern Hemisphere sea-ice extent and sea-ice area for each model.
- Combines all processed models into a single multi-model dataset.

#### Method

For each model:

- Reads the preprocessed `siconc` simulation together with the corresponding `areacello` file.
- Applies model-specific coordinate/dimension adjustments where necessary to align `siconc` and `areacello` on their native grids.
- Computes:
  - **Sea Ice Extent (SIE):** sum of the area of all grid cells with `siconc ≥ 15%`.
  - **Sea Ice Area (SIA):** sum of `siconc × areacello`.
- Calculates both quantities separately for the Northern and Southern Hemisphere.

#### Output

Individual model files:

```text
SIE_SIA_<model>_<experiment>.nc
```

containing:

| Variable | Description |
|----------|-------------|
| `SIE_NH` | Northern Hemisphere Sea Ice Extent |
| `SIE_SH` | Southern Hemisphere Sea Ice Extent |
| `SIA_NH` | Northern Hemisphere Sea Ice Area |
| `SIA_SH` | Southern Hemisphere Sea Ice Area |

Final multi-model dataset:

```text
SIE_SIA_<experiment>.nc
```

with dimensions:

```text
(model, year, month)
```

#### Notes

- Uses the standard **15% sea-ice concentration threshold** for SIE.
- Grid-cell areas are taken from the corresponding `areacello` files.
- Model-specific handling is limited to coordinate and dimension conventions; no regridding is performed.
- Optional sea-ice diagnostics such as `siarean`, `siareas`, `siextentn`, and `siextents` are not used.
- Individual model files are merged into a single dataset during the final processing step.
- The preprocessed `siconc` files are intermediate files and can be removed after the SIA/SIE calculation to clean up storage space.


### `SIA-SIE_computation_OBS.py`

Calculates Antarctic sea-ice area (SIA) and sea-ice extent (SIE) from satellite-based observational sea-ice concentration (SIC) products.

#### Data access

Observational SIC products were obtained from satellite-based datasets consistent with those used by Roach et al. (2020) for the evaluation of CMIP6 Antarctic sea ice.

SIC data were obtained from the Copernicus Climate Data Store for OSI SAF ([https://doi.org/10.24381/cds.3cd8b812](https://doi.org/10.24381/cds.3cd8b812)), and from the National Snow and Ice Data Center for the NASA Team ([https://doi.org/10.5067/MPYG15WAA4WX](https://doi.org/10.5067/MPYG15WAA4WX)) and Bootstrap ([https://doi.org/10.5067/X5LG68MH013O](https://doi.org/10.5067/X5LG68MH013O)) algorithms.

The downloaded SIC files were time-merged prior to the calculation of sea-ice diagnostics.

#### Method

For each observational product, the script:

- calculates sea-ice area (SIA) from fractional SIC using the native 25 km grid-cell area,
- calculates sea-ice extent (SIE) using a 15% SIC threshold,
- restricts the analysis to 1979–2024,
- calculates annual-mean SIA and SIE time series for comparison with CMIP6 simulations,
- combines the three observational products into a single NetCDF dataset while retaining the individual products separately.

#### Notes
- The downloaded sea ice concentration files can be removed after to clean up storage space.


## 3. Compute feedback TOA fluxes

### `compute_feedback-TOA-fluxes/<feedback>.py`

Computes TOA radiative feedback fields in W/m² for individual climate feedback components using the radiative-kernel method implemented in the `climkern` package.

The scripts operate on preprocessed CMIP6 monthly data generated by the preceding preprocessing scripts.

#### Purpose

For each CMIP6 model and each available radiative kernel, the scripts calculate the radiative feedback contribution associated with an individual physical process from `piControl` and `abrupt-4xCO2` simulations.

Separate scripts are provided for:

- `surface-albedo.py`
- `temperature.py`
- `water-vapour.py`
- cloud-feedback inputs, which are calculated separately in the subsequent feedback workflow.

Where applicable, both all-sky and clear-sky feedback components are calculated.

#### Input data

The required input variables depend on the feedback component:

- **Surface-albedo feedback:** `rsus` and `rsds` from `piControl` and `abrupt-4xCO2`.
- **Temperature feedbacks:** `tas`, `ta`, and `ps` from `piControl` and `abrupt-4xCO2`.
- **Water-vapour feedback:** `ta` from `piControl`, and `hus` and `ps` from `piControl` and `abrupt-4xCO2`.
- **Additional radiative fluxes:** `rlut`, `rlutcs`, `rsut`, `rsutcs`, and `rsdt`.

#### Method

For each model:

- Reads the required preprocessed CMIP6 variables from the `piControl` and `abrupt-4xCO2` simulations.
- Computes the radiative feedback using the corresponding function from the `climkern` package.
- Repeats the calculation for each available radiative kernel.
- Stores the resulting monthly feedback fields on the native model grid.

Each model–kernel combination is processed independently to limit memory usage.

#### Output

The scripts produce NetCDF files containing monthly feedback fields on the native model grid. For example:

```text
SA_<model>_<kernel>.nc
SA_cs_<model>_<kernel>.nc
Planck_<model>_<kernel>.nc
Planck_cs_<model>_<kernel>.nc
LR_<model>_<kernel>.nc
LR_cs_<model>_<kernel>.nc
WV_<model>_<kernel>.nc
WV_cs_<model>_<kernel>.nc
```

#### Notes

- These calculations are computationally demanding, particularly for high-resolution models, and therefore require substantially higher computing resources than the preceding preprocessing steps. For the highest-resolution models, up to approximately 265 GB of memory was allocated, with calculations distributed across multiple computing nodes where necessary.


## 4. Feedbacks

The feedback scripts calculate climate feedback parameters in W/m²/K, effective radiative forcing (ERF), and equilibrium climate sensitivity (ECS) from the pre-calculated TOA feedback responses via the Gregory regression method.

### `compute_feedbacks_global-mean.py`

Computes global annual-mean feedback parameters.

#### Purpose

- Calculates ECS, ERF (SW/LW, all-sky/clear-sky), and net feedback parameters.
- Derives individual kernel-based feedback components:
  - Planck feedback (PF)
  - Lapse-rate feedback (LRF)
  - Water-vapour feedback (WVF)
  - Surface-albedo feedback (SAF)
- Computes cloud feedbacks (CF_SW, CF_LW) using the adjustment method.
- Stores regression variables (`dT`, `dR_*`) for diagnostics.

#### Method

The script applies Gregory regression to the CMIP6 `abrupt-4xCO2` experiments relative to `piControl` and derives ECS, ERF, and net feedback from the Gregory regressions. Decomposed feedback parameters are derived from the preprocessed TOA feedback fields computed in the previous step (```SA_<model>_<kernel>.nc```, ...)

#### Output

Outputs are stored as NetCDF datasets containing global annual-mean climate sensitivity, forcing, and feedback diagnostics for models and kernels with the required input data.


### `compute_feedbacks_on-grid.py`

Computes feedback parameters on each model's native grid with monthly resolution.

#### Purpose

- Uses the global annual-mean temperature response as the regression predictor while retaining the monthly and spatial dimensions of the feedback fields.
- Derives spatially resolved:
  - ERF and net feedbacks,
  - kernel-based feedback components,
  - cloud feedbacks.
- Remaps the native-grid results to a fixed 2.5° × 2.5° regular latitude–longitude grid for multi-model comparison and plotting.

#### Method

As for deriving the global means, but the resulting feedback fields retain their monthly and spatial dimensions.

#### Output

Outputs are saved as NetCDF datasets containing spatially and monthly resolved climate sensitivity, forcing, and feedback diagnostics for models and kernels with the required input data.

The remapped results are combined on a fixed 2.5° × 2.5° regular latitude–longitude grid for multi-model analysis.


## OPTIONAL `Gregory-ECS_preprocessing.py`

If you only need ECS, the global net climate feedback parameter, and ERF from `tas`, `rlut`, `rsut`, and `rsdt`, this script provides a simplified and computationally efficient alternative to the full feedback-kernel workflow.

#### Purpose

- Reads the preprocessed `piControl` and `abrupt-4xCO2` simulations generated by `cmip_preprocessing.py`.
- Identifies models with complete data for the required variables (`tas`, `rsdt`, `rsut`, `rlut`).
- Computes global-annual mean surface temperature and TOA radiative imbalance.
- Removes internal variability by subtracting a **21-year running mean** of the `piControl` simulation, following Caldwell et al. (2016) and Zelinka et al. (2020).
- Performs a Gregory regression of TOA radiative imbalance against global-mean surface temperature anomaly.
- Derives model-specific estimates of:
  - Equilibrium Climate Sensitivity (ECS)
  - Effective Radiative Forcing for 2×CO₂ (ERF₂ₓCO₂)
  - Net climate feedback parameter (λ)

The script also provides a rapid overview of the model-specific Gregory regressions, avoiding the substantially more computationally demanding feedback-kernel calculations.

#### Output

Creates a multi-model dataset:

```text
ecs_feedbacks_erf_allmodels.nc
```

containing:

| Variable | Description |
|----------|-------------|
| `d_tas` | Global-annual mean surface temperature anomaly |
| `d_r` | Global-annual mean TOA radiative imbalance anomaly |
| `ecs` | Equilibrium Climate Sensitivity (K) |
| `erf2x` | Effective Radiative Forcing for 2×CO₂ (W m⁻²) |
| `λ` | Net climate feedback parameter (W m⁻² K⁻¹) |

#### Notes

- Gregory regressions are performed independently for each model.
- The resulting dataset provides baseline ECS, ERF, and net feedback estimates for rapid assessment and comparison with the full feedback decomposition.
- The script includes optional diagnostic plotting routines for inspecting the Gregory regressions across individual models.
- All input files can be removed after to clean up storage space.
